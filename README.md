# MIFI-Agent

Минимальный RAG-ассистент для вопросов по PDF с текстовым слоем. Проект запускается локально, интерфейс — Streamlit, векторы для поиска считаются локально, ответы генерирует GigaChat API. GPU и отдельный сервер БД не нужны. Подготовлен для Python 3.11–3.12; доступные проверки выполнены на Linux/Python 3.12, не на macOS.

RAG означает «поиск перед ответом». Сначала программа находит фрагменты в ваших материалах, затем передаёт их языковой модели. Модель получает вопрос и найденные тексты, а не всю папку учебников.

## Стек и архитектура

| Задача | Решение | Зачем |
|---|---|---|
| Чтение PDF | PyMuPDF | Извлекает текст отдельно с каждой страницы |
| Разбиение | Собственный chunker | Перекрывающиеся фрагменты, без смешивания страниц |
| Векторы поиска | Локальный хеш слов и символьных триграмм | Работает без ключа, интернета и скачивания модели |
| Хранение | SQLite | Хранит фрагменты, страницы, модель и векторы одним файлом |
| Поиск | NumPy, косинусное сходство | Точный перебор для небольшого учебного корпуса |
| Генерация | GigaChat `GigaChat` | Готовит ответ на основе найденного контекста |
| Интерфейс | Streamlit | Форма вопроса и раскрываемые источники |
| Проверки | pytest, HTTP MockTransport, Streamlit AppTest | Тесты без ключа и платных запросов |

Поиск использует совпадения слов и их частей. Формы слова могут находиться, но поиск по синонимам, перефразированным вопросам или между языками ограничен. Генерация обращается к GigaChat за токеном и ответом. Доступность генерации зависит от квоты вашего аккаунта.

## Быстрый запуск после установки зависимостей

Создайте `.env` из `.env.example` или перенесите свой `.env` из прежней папки проекта. Вставьте Authorization key в `GIGACHAT_CREDENTIALS` и запустите одну команду:

```bash
python -m streamlit run app.py
```

В боковой панели выберите методичку → нажмите «Сохранить PDF» → «Индексировать PDF» → задайте вопрос. Запуск, сохранение и индексация PDF работают без ключа. При ответе GigaChat получает вопрос и найденные фрагменты, а расход токенов зависит от вашего тарифа.

Индексация: PDF → страницы → фрагменты → эмбеддинги → SQLite.
Ответ: вопрос → эмбеддинг → top-k фрагментов по сходству → LLM → проверка номеров ссылок → ответ и источники.

Номер страницы — физическая страница PDF, начиная с 1. Он может отличаться от напечатанного номера. Фрагмент всегда принадлежит одной странице. Ссылка `[1]` означает первый фрагмент текущего поиска; имя документа и страница берутся из индекса, а не из текста LLM. Проверка номера ссылки не доказывает правильность утверждения.

## 1. Виртуальное окружение

Распакуйте архив и откройте терминал в `MIFI-Agent`. На macOS установите Python 3.11 или 3.12, затем:

```bash
python3 -m venv .venv
source .venv/bin/activate
python --version
```

Все следующие команды выполняются из корня проекта. На Windows активация: `.venv\Scripts\activate`.

## 2. Зависимости

```bash
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m pip check
```

Прямые зависимости зафиксированы. `constraints.txt` ограничивает транзитивные зависимости; `requirements-lock.txt` записывает фактически установленное окружение проверки. Библиотеки используют CPU. На macOS не требуется CUDA. Наличие подходящих колёс пакетов зависит от версии Python и ОС; рекомендуются Python 3.11–3.12.

## 3. API-ключ и настройки

```bash
cp .env.example .env
```

Откройте `.env` в корне проекта и заполните:

```dotenv
GIGACHAT_CREDENTIALS=ваш_Authorization_key
GIGACHAT_SCOPE=GIGACHAT_API_PERS
```

Нужен **Authorization key**, а не Client ID, не отдельный Client Secret и не временный Access token. Вставляйте значение без префикса `Basic`; приложение само обменивает его на короткоживущий токен и обновляет токен при истечении срока. Ключ не логируется, тела ошибок API не показываются пользователю. Файл `.env` исключён из Git.

Где получить ключ: [регистрация проекта GigaChat API](https://developers.sber.ru/docs/ru/gigachat/quickstart/ind-create-project). Войдите в личный кабинет Studio по ссылке из инструкции, создайте проект GigaChat API и сгенерируйте Authorization key. Значение Scope возьмите из своего проекта; по умолчанию в приложении выбран доступ для физических лиц `GIGACHAT_API_PERS`.

Важно для новых подключений: в [актуальном быстром старте](https://developers.sber.ru/docs/ru/gigachat/individuals-quickstart) указано, что с 1 сентября 2026 года покупка новых пакетов для новых клиентов перенесена на cloud.ru. Условия доступа и доступные модели проверяйте в своём кабинете. Этот адаптер реализует GigaChat REST с OAuth Authorization key; ключ другого сервиса, включая Cloud.ru Foundation Models, нельзя подставлять как совместимый без проверки протокола. Успешная авторизация с настоящим ключом здесь не проверялась.

### Сертификат TLS

В `certs/russian_trusted_root_ca.pem` приложен публичный корневой сертификат НУЦ Минцифры с официального адреса, указанного в [документации GigaChat](https://developers.sber.ru/docs/ru/gigachat/certificates). Он добавляется только в контекст HTTPS-клиента приложения. Системное хранилище и certifi не изменяются. Проверка сертификатов и имени сервера включена всегда. Для другого доверенного PEM-файла задайте `GIGACHAT_CA_BUNDLE_FILE`; источник и отпечаток приложенного сертификата записаны в `certs/README.md`.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| GIGACHAT_CREDENTIALS | пусто | Authorization key для ответов |
| GIGACHAT_SCOPE | GIGACHAT_API_PERS | Scope из проекта GigaChat |
| GIGACHAT_MODEL | GigaChat | Модель генерации |
| GIGACHAT_BASE_URL | https://api.giga.chat/v1 | Базовый URL REST API |
| GIGACHAT_AUTH_URL | https://ngw.devices.sberbank.ru:9443/api/v2/oauth | Получение токена |
| GIGACHAT_CA_BUNDLE_FILE | certs/russian_trusted_root_ca.pem | Дополнительный доверенный сертификат |
| GIGACHAT_TIMEOUT | 60 | Таймаут HTTP-запроса в секундах |
| PDF_DIR | data/pdfs | Каталог PDF, включая подпапки |
| INDEX_PATH | data/index.sqlite | Файл индекса |
| CHUNK_SIZE | 1000 | Символов в фрагменте, максимум 2000 |
| CHUNK_OVERLAP | 150 | Перекрытие соседних фрагментов |
| TOP_K | 5 | Максимальное число источников на вопрос |
| MIN_SIMILARITY | 0.25 | Порог косинусного сходства от -1 до 1 |
| MAX_UPLOAD_MB | 20 | Лимит загрузки одного PDF в МБ |
| LOG_LEVEL | INFO | Уровень логирования |

Размер считается в символах, не токенах. Порог 0.25 — начальная настройка, а не измеренный оптимум. Сходство не является вероятностью правильности. Все относительные пути в настройках отсчитываются от корня проекта.

При генерации вопрос и найденные фрагменты передаются в GigaChat. Для ответов нужны сеть и доступная квота генерации. Индекс хранит исходный текст локально.

## 4. PDF и демонстрационные материалы

Загрузите PDF через боковую панель и нажмите «Сохранить PDF» либо поместите их в `data/pdfs/`. Загрузка только сохраняет и проверяет файл локально. Пустые файлы, сканы без текстового слоя, некорректные PDF и файлы сверх лимита отклоняются. Файлы с одинаковым именем и разным содержимым сохраняются раздельно с хешем в имени; исходник не перезаписывается. Имя относительно этой папки становится идентификатором документа, например `physics/lecture.pdf`. Пустые страницы сохраняют свою позицию, но не создают фрагменты. Сканы без текста и защищённые паролем документы отклоняются; повреждённый PDF прерывает пересборку, сохраняя прежний индекс.

Для воспроизводимой демонстрации без реальных методичек:

```bash
python -m scripts.make_demo
```

Команда создаёт `synthetic_a.pdf` и `synthetic_b.pdf`, суммарно пять страниц. Это вымышленные документы на английском о вымышленной единице `lum`, без отношения к методичкам МИФИ. Для поиска по этим файлам используй английские термины из PDF, например `lum`. Повторный запуск не перезаписывает существующие файлы. Исходный текст примера находится в `data/synthetic_documents.json`.

Для оценки по примеру используйте отдельный корпус только из этих двух PDF. Приложенная презентация проекта не включена в репозиторий и не используется как эталон учебного содержания.

## 5. Индексация

```bash
python -m scripts.ingest
```

Полная пересборка заменяет прежний индекс после чтения PDF и локального расчёта векторов. Удалённые PDF исчезнут из новой версии индекса. После перехода с GigaChat Embeddings нажмите «Индексировать PDF» один раз, чтобы заменить старые векторы. Новый идентификатор индекса — `local:lexical-hash-v1`. Не запускайте несколько пересборок одновременно.

## 6. Интерфейс

```bash
python -m streamlit run app.py
```

Откройте адрес из терминала, обычно `http://localhost:8501`. После загрузки и сохранения PDF обновите индекс кнопкой «Индексировать PDF» в боковой панели. Задайте вопрос и раскройте источники под ответом: там отображаются документ, PDF-страница и точный найденный текст. Если поиск не дал фрагментов выше порога, система возвращает отказ без обращения к генератору. Если фрагменты нерелевантны, отказаться должна модель — это нужно тестировать.

Ссылки с несуществующими номерами и фактические ответы совсем без ссылок отклоняются. Полнота цитирования каждого утверждения и смысловое соответствие источнику не гарантируются программной проверкой. В текущей версии каждый вопрос независим, истории диалога нет.

## 7. Тесты

```bash
python -m pytest -q
python -m compileall -q app.py config.py rag evaluation scripts tests
```

Тесты не требуют API-ключа. Автоматическая фикстура запрещает настоящий сетевой HTTPX-транспорт: обращения к GigaChat могут выполняться только через `MockTransport`. В них есть искусственные PDF, заранее заданные векторы и HTTP-ответы. Они проверяют алгоритмы и соединение модулей, а не качество реальных эмбеддингов или LLM. Проверяются границы страниц, перекрытия, повреждённые PDF, сортировка поиска, порог, несовместимость моделей, откат транзакции, ссылки, отказ, OAuth, кеш токена и обновление по сроку/401, безопасные сообщения об ошибках, отсутствие повторов при таймауте, проверка TLS, валидация загрузок, метрики и полный сценарий Streamlit «сохранить PDF → индексировать → задать вопрос» с подменённым HTTP.

## 8. QA-датасет

CSV и JSON содержат одинаковые шесть полей:

| Поле | Тип JSON | Значение |
|---|---|---|
| question | string | Вопрос |
| expected_answer | string | Эталонный ответ |
| expected_document | array[string] | Документы эталонных фрагментов |
| expected_page | array[integer] | Физические PDF-страницы, начиная с 1 |
| expected_context | array[string] | Эталонные тексты, достаточные для ответа |
| question_type | string | Категория |

Массивы документов, страниц и контекстов сопоставляются по позиции. Несколько элементов могут ссылаться на один документ. Для вопроса без ответа все три массива пусты. В CSV массивы записаны как JSON внутри стандартно экранированных CSV-ячеек; читайте через `csv.DictReader`, а не разделением строки по запятой.

Категории: `definition` — определение, `formula` — формула, `theorem` — объяснение теоремы, `multi_fragment` — несколько фрагментов одного документа, `multi_document` — несколько документов, `unanswerable` — ответа нет. Пример записи:

```json
{
  "question": "Что такое lum в искусственном документе?",
  "expected_answer": "Вымышленная единица накопленного света.",
  "expected_document": ["synthetic_a.pdf"],
  "expected_page": [1],
  "expected_context": ["A lum is a fictional unit of stored light."],
  "question_type": "definition"
}
```

Шесть примеров демонстрируют формат, но недостаточны для статистического вывода. Для реального корпуса QA-инженер читает PDF и вручную создаёт эталоны, проверяя физическую страницу. Разделите вопросы для настройки порога и финального измерения; добавьте перефразировки и сложные отрицательные примеры. Не заполняйте эталоны выдуманным содержанием.

## 9. Оценка качества RAG

Используются именно четыре требуемые метрики, без подмены совпадением слов или косинусным сходством. Реализован воспроизводимый режим с ручной разметкой: LLM-судья сейчас не подключён. Автоматизация семантических суждений в будущем потребует отдельного LLM-судьи, его промпта, версии модели и проверки согласованности с человеком.

| Метрика | Определение реализации | Необходимые данные |
|---|---|---|
| Faithfulness | Число утверждений ответа, подтверждённых найденными текстами / число всех проверяемых утверждений ответа | Разбиение ответа на атомарные утверждения и ручные метки подтверждения; эталонный ответ не обязателен. Для автоматического режима нужен LLM-судья |
| Context Precision | Average Precision по ранжированным фрагментам: `sum(P@k * rel_k) / sum(rel_k)` | Ручные метки релевантности каждого найденного фрагмента относительно вопроса и эталона; автоматическая оценка требует LLM-судьи или полной разметки релевантности |
| Context Recall | Число эталонных фактов, покрытых найденными фрагментами / число необходимых эталонных фактов | Проверенный эталон ответа/контекста, разбиение на факты и ручные метки покрытия; автоматический семантический режим требует LLM-судьи |
| Citation Accuracy | Число корректных вхождений ссылок / число всех вхождений ссылок в ответе | Ручная проверка PDF: документ, физическая страница и подтверждение связанного утверждения. Проверка номера `[N]` сама по себе недостаточна |

`P@k` — доля релевантных фрагментов среди первых k. В Context Precision знаменатель — число релевантных фрагментов среди полученных top-k, а не число всех релевантных фрагментов в базе. Поэтому пропущенную необходимую информацию учитывает Context Recall. При непустой выдаче без релевантных фрагментов Context Precision = 0.

### Получение реального прогона

После создания искусственных PDF, настройки ключа и индексации:

```bash
python -m evaluation.evaluate run --dataset data/test_questions.json --output reports/review.json
```

Можно передать `data/test_questions.csv`. Команда вызывает настоящий пайплайн и записывает ответы, ранжированные контексты, каждое вхождение ссылки с позицией в ответе, эталон и пустую разметку. Ошибки записываются отдельно и не становятся нулевыми оценками. Генерация расходует доступную квоту GigaChat.

### Ручная проверка

Откройте `reports/review.json`. Для каждого успешного вопроса заполните `annotation`:

1. `claims`: список атомарных проверяемых утверждений ответа в порядке чтения. `claim_supported`: по одной целочисленной метке `1` или `0` на утверждение. 1 означает, что утверждение полностью подтверждается найденным контекстом; неподтверждённые и противоречащие факты получают 0. Не оценивайте по общим знаниям.
2. `context_relevant`: по одной метке 0/1 на элемент `contexts` в исходном порядке поиска. 1 означает, что фрагмент содержит информацию, полезную для правильного ответа на вопрос. Не сортируйте выдачу при разметке.
3. `reference_facts`: разложите проверенный `expected_answer` и `expected_context` на необходимые для ответа атомарные факты. `reference_fact_found`: метки 0/1, покрывает ли найденная выдача каждый такой факт. Смотрите все найденные фрагменты вместе, а не только процитированные.
4. `citation_correct`: по одной метке 0/1 на каждое вхождение в `citations`. Найдите утверждение перед ссылкой по `answer_offset`, откройте оригинальный PDF, перейдите на указанную физическую страницу. Поставьте 1 только при правильном документе, странице и подтверждённом утверждении. Повторные ссылки оцениваются отдельно. Проверьте весь смысл утверждения, включая условия формул.
5. Укажите `reviewer` и причины спорных решений в `notes`. Для надёжности второй проверяющий независимо размечает часть примеров, затем расхождения обсуждаются.

Образец **учебной разметки, не результата тестирования**:

```json
{
  "claims": ["lum — вымышленная единица накопленного света"],
  "reference_facts": ["lum — вымышленная единица накопленного света"],
  "claim_supported": [1],
  "context_relevant": [1, 0],
  "reference_fact_found": [1],
  "citation_correct": [1],
  "reviewer": "ФИО проверяющего",
  "notes": "Проверено по synthetic_a.pdf, физическая страница 1"
}
```

Количество `context_relevant` и `citation_correct` должно совпадать с числом объектов в конкретном прогоне; пример с двумя фрагментами не копируется механически. `null` означает «не размечено», `[]` — нет объектов для оценки. Дробные и логические метки запрещены.

```bash
python -m evaluation.evaluate score reports/review.json > reports/metrics.json
```

Отчёт показывает макросреднее по размеченным вопросам, число размеченных вопросов для каждой метрики и число ошибок. Без разметки значения `null`; это не ноль. Нулевой знаменатель (нет утверждений, ссылок или эталонных фактов) даёт `null` и исключается из среднего. Поэтому Citation Accuracy не штрафует отсутствие ссылок; отдельно проверьте полноту цитирования вручную и учитывайте число оценённых вопросов.

Для `unanswerable` эталонных содержательных фактов нет: `reference_facts=[]`, `reference_fact_found=[]`, Context Recall неприменим. Для чистого отказа Faithfulness и Citation Accuracy также неприменимы. В `notes` вручную отметьте, корректен ли отказ, и проверьте, не придумала ли система ответ. Нерелевантные полученные фрагменты получают 0. Эти наблюдения не выдаются за пятую требуемую метрику.

Реальных измерений качества RAG в поставке нет: ключ не предоставлен, корпус учебных PDF и эталоны не размечены. Числа в unit-тестах — проверка арифметики на заранее заданных метках, не результаты качества системы.

## Ограничения

- Базовый RAG не планирует повторный поиск и не является Agentic RAG. Система может пропустить сведения за пределами top-k, особенно для вопросов по нескольким документам.
- PDF должен иметь текстовый слой. Многоколоночная вёрстка, таблицы и математические символы могут извлекаться с ошибками. Формулы не распознаются специализированным математическим OCR.
- Разбиение по символам может разорвать предложение. Перекрытие снижает, но не устраняет проблему.
- Даже существующая ссылка может не подтверждать ответ. Нужны ручная проверка цитат и размеченная оценка.
- Инструкция отвечать только по контексту уменьшает галлюцинации, но не гарантирует их отсутствие и не является полной защитой от инструкций внутри PDF.
- Все векторы загружаются в память для каждого поиска: решение для небольшого корпуса, не для миллионов фрагментов. При индексации тексты и векторы также собираются в памяти.
- У API есть тарифы, лимиты, задержки и ограничения доступа. Таймаут по умолчанию 60 секунд. При сетевой ошибке/таймауте и 429/5xx платные операции автоматически не повторяются: сервер уже мог обработать запрос. При 401 токен обновляется и отклонённый запрос повторяется ровно один раз. При новой операции после завершения предыдущей токен может запрашиваться заново; постоянного дискового кеша токенов нет.
- Нет учётных записей, разграничения доступа, истории чата или встроенного просмотра PDF. Это локальный учебный прототип.
- Точные номера моделей и воспроизводимость ответа зависят от внешнего сервиса; фиксирование библиотек не фиксирует поведение LLM.

## Модульное развитие — только проектирование

| Расширение | Точка подключения |
|---|---|
| Agentic RAG | Отдельный оркестратор вокруг `Retriever` и `Generator`, с лимитом повторных поисков |
| Telegram-бот | Новый адаптер интерфейса вызывает `Pipeline.ask`, как Streamlit |
| Гибридный поиск | Альтернативный retriever объединяет векторный и лексический поиск |
| Reranking | Этап между `retrieve` и `generate` с сохранением идентификаторов источников |
| OCR | Дополнительная стратегия в PDF parser для страниц без текста |
| Расширенные метрики и LLM-судья | Отдельные оценщики в `evaluation`, с сохранением сырых суждений |

Эти возможности не реализованы и не требуются для запуска текущей версии. Протоколы `Embedder` и `Generator` позволяют заменять поставщика, не переписывая UI. Для нового поискового движка достаточно сохранить выход `list[Hit]`.

## Как объяснить проект на защите

1. Программа читает PDF постранично, чтобы сохранить проверяемый адрес информации.
2. Короткие фрагменты преобразуются в векторы. Вектор описывает содержание текста числами.
3. Вектор вопроса сравнивается с векторами фрагментов; близкие по смыслу тексты получают большее сходство.
4. LLM получает только найденные тексты и формирует ответ со ссылками.
5. Пользователь раскрывает источники и проверяет страницу. QA оценивает поиск, покрытие, подтверждённость ответа и корректность цитат отдельно.

Для демонстрации создайте искусственные документы, проиндексируйте их, задайте вопрос об определении lum, затем вопрос о массе устройства (в документах её нет). Покажите источники и отказ. Не обещайте успешный отказ до реального прогона: модель может ошибиться, и именно это должен выявить QA.

Для размещения на GitHub создайте собственный репозиторий и загрузите проект без `.venv`, `.env`, пользовательских PDF, индекса и отчётов. Проверьте права на распространение документов и лицензии зависимостей, в частности PyMuPDF (AGPL/commercial), перед выбором лицензии проекта.
